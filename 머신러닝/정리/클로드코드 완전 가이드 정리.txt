1.분할정복
  로그인 페이지를 만들어줘 이런식의 큰 요청보다는
	1.“사용자 모델을 위한 데이터베이스 스키마를 설계해줘. 필드는 username, email, password_hash, created_at,
		updated_at이 필요해.”
	2. “이 스키마를 바탕으로 Drizzle ORM 마이그레이션 파일을 생성해줘.”
	3. “React와 TailwindCSS를 사용하여 로그인 폼 UI 컴포넌트를 만들어줘. 이메일과 비밀번호 입력 필드, 그리고 ʻ로그인’ 버튼이
		필요해.”
	4. “사용자명과 비밀번호를 받아 /api/auth/login 엔드포인트로 POST 요청을 보내는 로직을 작성해줘.”
	5. “로그인 성공 시 토큰을 localStorage에 저장하고 대시보드로 리다이렉트하는 로직을 추가해줘.”
	6. “로그인 실패 시나리오(잘못된 비밀번호, 존재하지 않는 사용자)에 대한 테스트 코드를 작성해줘.”
  이런식의 단계적인 순서로 ai가 뭘 할지 명확하게 가이드라인을 주어야함
  즉 작업을 분해하고,하나씩 완성하고 검증한후 다음단계로 넘어가는 방식을 취해야함
  만약 문제가 있으면 그단계만 수정하면됨

2.욜로vs플랜
  플랜모드는 우리가 승인하기전까지 아무것도 하지않고,계획만 쭉 짜는데,이땐
    코드베이스를 읽고 분석
	아키텍처파악
	의존성탐색
	구현계획(플랜) 단계별 작성
  이걸 순서대로 진행함,단 우리가 플랜을 승인하기전까지는 아무것도 하지않음 
  
  보통 90%의 시간을 플랜모드를 사용하게됨
  이건
    처음해보는 복잡한 작업
	여러파일에 걸친 대규모 리팩토링
	아키텍처변경이 필요한 작업
	실수시 복구비용이 큰 작업(db 마이그레이션등)
  을 할때 사용함
  
  욜로모드는 그냥 바이브코딩임
  이건
    간단하고 명확한 작업
	실험적인 프로토타입 작업
	컨테이너안에서 격리된 환경에서 작업할때
	반복적이고 시간이 많이걸리는 작업(대량의 파일처리)
  에서 사용함,이때 호스트시스템에서 직접 사용하진 않아야함(뭔짓할지모름)
  
3.컨텍스트  
  가장 중요한건 컨텍스트고,컨텍스트는 신선하고,압축된 상태를 유지해야함
  이걸위해서
    단일목적대화:하나의 대화(세션)에선 하나의 명확한 목표에만 집중,특정기능을 구현했으면 초기화후 다시 시작
	선제적압축:대화가 길어지면 다음에이전트를 위해 handoff.md파일을 작성하게하고 클리어후 시작
	/context:저 명령어로 현재 컨텍스트가 뭘로 차있는지를 확인할수있음
	자동압축비활성화:자동압축도 토큰을 차지하기때문에 수동으로 관리하는게 더 효율적일수있음,또한 핸드오프방식이 더 명확하고 검증가능함
	
  선제적압축을 위해서 다음같은 프롬프트를 사용할수있음	
	Put the rest of the plan in the system-prompt-extraction folder as HANDOFF.md. Explain what you have tried,
	what worked, what didn’t work, so that the next agent with fresh context is able to just load that file and nothing
	else to get started on this task and finish it up.”  
  
4.올바른 추상화 수준 선택 
  바이브코딩과 딥다이브는 상황에 맞게 선택해서 써야함
  바이브코딩은 전체구조와 흐름만 파악하고,개별코드라인은 신경쓰지않는것
  이건
    일회성 프로젝트나 프로토타입
	중요하지않은 코드베이스부분
	빠른실험이 필요할때
  사용하기좋음
  
  딥다이브는 파일구조,함수,개별코드라인,의존성까지 꼼꼼하게 검토
  이건
    프로덕션 코드
	보안이 중요한 부분
	복잡한 버그 디버깅
	성능 최적화
  에 사용됨
  
  중요한건 현재 상황에 맞는걸 사용하는것
  
  예를들어 새로운 기능을 추가할땐
    1.높은추상화:사용자 프로필 페이지를 만들어줘->전체 구조 파악
	2.중간추상화:프로필편집폼의 유효성 검사 로직을 보여줘->특정기능 검토
	3.낮은추상화:이 정규식이 왜 이메일 유효성 검사에 실패하는지 설명해줘->세부디버깅
  이런식으로 사용하는것
 
5.미지의 영역에서 더 용감하게
  해본적 없는 문제도 이런방식으로 해결할수있음
	1.초기시도:클로드가 제안한 솔루션을 시도->동작하지않음
	2.속도조절:천천히 가자,이줄이 정확히 어떤 의미인지 설명해줘
	3.방향전환:막다른골목이면 다른 접근방식 탐색
	4.깊이조절:필요에 따라 추상화수준을 높이거나 낮춤
	5.최종해결:솔루션 발견
